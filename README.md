# 给小雨的软件

Windows 账务、物流与发票工具，使用 PySide6。银行流水、工资、物流和发票均支持 XLS/XLSX 自动识别列名、手动确认对应关系、记住读取格式。银行与工资资料可继续生成柠檬云凭证。独立的“财务 AI 助手”支持通过 OpenAI 云端进行财务问答、分析上传文件、生成文档，以及按规则更新已绑定的 WPS 云表。

## 通用资料导入（第一期）

1. 选择当前公司／账套，在四个入口中选择或拖入 Excel。
2. 点击“识别列名，确认导入”，勾选工作表、确认表头行及列对应。识别不出的列可以手动指定。银行可使用收入／支出两列，或金额列配合收支方向；两种方式不能同时选择。
3. 工资需明确所属年月；物流可选商品收发货或运输与运费；发票可选收到或开出。单金额银行表遇到负数默认待核对，确认负数含义后可选择按方向取绝对值，或保留负数作为冲回。
4. 勾选记住格式后，同公司、同资料类型、相同表头可复用对应关系，仍需确认。工资默认年月不会记入读取格式，避免次月误用。
5. 资料核对页按类型、月份、关键词及待核对状态筛选；双击可查看原始行。错误记录保留，但不参与凭证生成。
6. 导出清单包含当前公司全部已保存资料：银行、工资、物流、发票、待核对及原始来源六张表。筛选仅影响查看。凭证生成使用当前公司的已保存银行与工资，再按凭证页月份选取；物流和发票一期仅用于资料管理。

资料副本、导入提示与读取格式保存在 `data/materials.sqlite3`，公司之间隔离；原始 Excel 不变。相同文件／类型／工作表／来源行再次导入会更新原记录，不新增一份；不同文件版本保留，业务字段完全相同的资料只提示疑似重复。可移除误导入的资料副本后重新导入，源文件不会被删除。切换公司分别保存生成规则、文件列表与凭证模板。

暂不支持 PDF／图片发票识别、自动关联三类资料或根据物流／发票自动记账。复杂合并表头需手动选择实际字段所在行，合并的业务单元格不会自动向下补值；真实样表还需逐种验证。发票一票多行明细全部保留，不按号码删除，也不逐行累加可能重复出现的整票金额。基础校验通过不代表已经核实票据有效性或抵扣资格。

## 财务 AI 助手

这是独立模块，不读取当前公司、已导入的资料或凭证，不执行模型生成的本地代码。用户明确选择附件、发送后，才把附件上传到 OpenAI。云端读取、计算并生成文件；用户选择保存位置后下载结果，不自动导入原业务模块或打开下载文件。用户主动关联已绑定的 WPS 链接后，助手还可通过受控工具读取相关云表数据并提交指定更新，相关数据会用于本次 AI 分析。

1. 点击左侧“财务 AI 助手”，打开“连接设置”，填写 OpenAI API 密钥。模型固定为 `gpt-6-luna`，API 地址固定为官方 `https://api.openai.com/v1`，没有自建中转服务器。
2. 默认直连。也支持系统代理和自定义 HTTP/HTTPS 代理；连接由运行软件的电脑发出。点击“测试连接”检查密钥和模型访问权限；连接成功不代表 API 余额足够或文档处理请求一定成功。
3. 可直接询问财务知识，或选择／拖入 `.xlsx`、`.csv`、`.pdf`、`.docx`、`.pptx`、`.txt`、`.md`、`.png`、`.jpg`、`.jpeg`。每个文件不超过 20 MiB，每次会话最多 10 个附件。旧 `.xls` 请先由用户在 Excel 中另存为 `.xlsx`；助手不会在本机转换文件。
4. 输入要求后发送，例如“按部门汇总这份工资表，检查合计，并生成 Excel”。财务金额由云端 Code Interpreter 计算；请检查返回的依据、假设、合计和生成文件。模型回答与借贷相等本身均不代表会计处理正确。
5. 需要核实当前税收政策时，勾选联网查询并明确地区、时间和纳税人情况；联网查询另计费用。没有开启联网时，助手应明确资料时效限制。
6. 生成文件会显示在结果列表，手动下载保存。云端处理环境约 20 分钟不活动后会过期，请及时下载；过期需要重新上传处理。新会话清除本机内存对话和附件引用，助手会尽力清理本会话上传的云端文件；上传文件同时设置 24 小时有效期。网络异常或直接退出时不能保证即时清理，服务端保留仍以 OpenAI 实际处理为准。
7. 点击页面右上方的“长期规则”，填写通用要求，例如“回答简洁，先给结论；需要操作时分步骤说明”。最多 4000 字，保存后从下一次提问起生效，不清空当前聊天；新对话和重启后仍会使用。清空内容并保存即可取消自定义规则。保存失败时窗口会保留输入，可修改后重试。

长期规则独立保存在本机 `data/finance_ai_rules.json`，每次提问随请求发送给 AI，不受最近聊天记录长度的限制。当前提问中的具体要求优先，软件内置的财务服务范围和金额核对要求仍然适用。规则不跨电脑自动同步，发行 ZIP 不携带本机规则；用户在新电脑上可自行填写。这不等于保存完整聊天记录，也不会自动读取“生成规则”栏目里的凭证规则。

API 密钥可仅用于本次打开，也可使用 Windows 当前用户的 DPAPI 加密保存在 `data/finance_ai.json`。密钥不会写入代码、安装包、普通账套设置或日志；加密设置复制到另一台电脑／另一 Windows 用户后需重新输入密钥。发行 ZIP 不包含 `data`。API 调用产生费用，需要可用的 API 余额和模型权限；ChatGPT/Codex 的剩余聊天额度不是 API 余额。

`data/finance_ai_usage.json` 只保存本机按北京时间自然月累计的次数、token 和费用估算，不保存聊天或附件正文。默认预算为 20 美元；发送前达到估算预算则暂停。它不是账户余额查询或平台硬性限额：未完成／取消请求、云端处理时间、其它设备用量和价格变动均可能导致估算与账单不同，单次请求也可能跨过预算。取消只停止本机等待，不保证取消服务器处理或计费。

模型可使用云端文档处理、可选网页查询，以及本次用户关联的 WPS 文档工具；不提供本地文件搜索、终端、宏、数据库或凭证写入工具。WPS 令牌和 webhook 由软件使用，不发送给模型。非财务及无关文档请求由助手规则限制，该限制不应被当作模型永远不会偏离主题的保证。对话仅保留于本次软件运行的内存中，云文档修改记录单独持久保存。

接口参考：[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、[Code Interpreter](https://developers.openai.com/api/docs/guides/tools-code-interpreter)、[API 价格](https://developers.openai.com/api/docs/pricing)。

### 更新 WPS 云文档（0.5.0 起）

1. 在财务 AI 页点击“云文档”，添加文档名称、金山分享链接、共享脚本 webhook 和脚本令牌。使用“复制配套云端脚本”把随软件提供的 `assets/wps_airscript.js` 完整粘贴到目标文档的 **AirScript 2.0 / Beta 文档共享脚本**，Ctrl+S 保存到云端。旧的 A15 验证脚本只用于测试，需替换成此通用脚本。
2. 确认 webhook 来自这份分享链接，进行只读连接测试。软件取得实际工作簿名（包括 `.xlsx` 后缀），保存绑定后每次调用都严格核对该名称。令牌使用 Windows 当前用户 DPAPI 加密保存在 `data/wps_documents.json`，不放进模型上下文或安装包。浏览器登录和 API 授权分开；令牌失效或权限变化时需要重新配置。
3. 在聊天中上传来源表、贴已绑定链接并描述规则，例如：“按业务单号匹配，把来源表的实收金额更新到汇总表的到账金额，只处理来源状态为已到账的记录，空白不覆盖。”首次出现的未绑定链接会提示配置；来源文件和目标文档均由本次用户主动选择。
4. 行号是可选的。AI 先读取表头预览，再按实际列名识别唯一表头和数据范围，使用业务编号（也可多个字段组合）匹配。多段同名表头或规则不清时需要补充说明，可点击助手给出的选项，也可在输入框自由回答。编号类型和前导零保留；文本编号 `001` 不自动等于数字 `1`。金额由云端 Python 按 Decimal/整数分计算。
5. “按要求自动处理”模式下，明确要求更新且规则齐全即可生成计划并执行；“只预览”或聊天中的只读要求禁止写入。已授权但尚未完成任务可以继续补充规则，完成后的新任务需要新的更新要求。仅发送一个链接不授权写入。预览不是完成状态。
6. 本版更新已有记录的单列常量；未匹配记录不动、来源空白默认跳过、0 是有效值。重复业务编号先澄清，已有公式与合并单元格不改；不新增/删除行列，不覆盖整份文件，不执行模型生成的本地代码或脚本。以 `=` 开头的普通文本暂不写入，以免被识别成公式。
7. 每批最多100条：先写本地任务记录，云端再次核对表头、业务键、旧值、公式、数字格式及筛选涉及的列，再保存，软件独立回读确认结果。协作编辑不是原子事务；发现变化会记录冲突，部分成功会明确显示。取消只停止后续批次，已发出的批次仍要核对。
8. 聊天结果和“云文档结果”区域显示原链接、更新/跳过/冲突/待核对数量。`data/wps_tasks/*.json` 保存本次涉及的旧值、新值和逐项结果，含业务数据，请按本机业务资料保管。历史任务可查看明细；出现网络超时，可在聊天中要求“核对任务 编号”。核对只读，不会重发写入；同一文档存在未核对任务时会阻止新写入。查看记录不等于自动撤销，不能覆盖其他人后续修改。

读取快照上限为5000行、20000格、30个选定列；单个修改计划最多2000条来源记录。超出会提示缩小范围，不会静默截断数据。实际性能还受 AirScript 执行时间和 AI 上下文限制影响。

工具通过普通 Responses function calling 顺序执行，保留多轮输出和 reasoning 状态；使用 `store:false`。业务工具实际结果与 AI 最后文字分开保存，AI 摘要失败也不会隐藏已经写入的部分。参考：[Function calling](https://developers.openai.com/api/docs/guides/function-calling)、[Conversation state](https://developers.openai.com/api/docs/guides/conversation-state)、[WPS HTTP API](https://airsheet.wps.cn/docs/apitoken/api.html)。

## 软件自动更新

从 0.4.0 起，免安装客户端在每次打开、界面显示后后台检查一次更新，运行期间没有定时轮询。左下角显示当前版本，并提供“检查更新”。发现新版后后台下载，显示进度和更新说明；普通关闭后更新且保持关闭，点击“立即重启更新”才在更新后重新打开。正在导入、导出或等待 AI 回答时会等待当前任务完成。断网、检查失败或下载中断不影响账务功能，下次打开时重新检查。

更新地址和 Ed25519 验证公钥保存在 `assets/update-channel.json`，随主程序和独立更新器一起打包；示例配置不会自动启用更新。当前使用 GitHub Releases 的 `https://github.com/shelleyaeel-rgb/excel-voucher/releases/latest/download/latest.json`。客户端不需要 GitHub 账号或发布凭证。GitHub 在部分国内网络上可能无法访问，此时保留现有版本，也可手动下载交付包。

客户端通过 HTTPS 读取签名版本清单，验证发布签名、版本兼容性、包大小和 SHA-256 后，才允许解压执行。独立更新器复制到程序目录外运行，等主程序完全退出、取得应用锁后，先运行隔离的 `--self-test`，备份旧程序和实际数据目录，再切换程序并运行隔离的 `--update-health-check`。程序文件归属由包内 `release-files.json` 记录，`data`、用户源表、导出结果及额外文件全部保留；重名、文件改动、链接路径、占用或校验失败会停止更新。当前只接受 `data_schema=1`，不自动执行不兼容的资料库升级。

更新备份和恢复记录位于程序目录同级 `.xiaoyu-update-<目录标识>/`。切换失败会恢复旧程序；断电等中断由下次启动调用目录外更新器恢复。若中断时启动程序暂时不在原目录，可运行该目录中 `helpers/<编号>/update-helper.exe` 恢复。已完成更新后不再自动回退用户新录入的数据；备份不会随意清理。更新过程中请保留整个软件目录及同级更新备份目录。

真实 Windows 更新验证可执行 `.venv/Scripts/python.exe scripts/verify_update.py --private-key <项目外签名私钥路径>`。它在 `outputs/qa/update-smoke/` 中创建合成资料，用发行包的真实独立更新器验证等待退出、签名、安装、自检、备份、长路径及资料完整性，不连接发布服务、不修改正式程序。旧安装只将清单版本设为 `0.0.0`，二进制仍来自本次包，因此这项验证不代替未来涉及历史资料格式变化时的升级兼容测试。

### 发布新版到 GitHub

首次配置只需执行一次（签名私钥必须保存在项目外，同一更新渠道以后始终使用这把私钥）：

```powershell
.venv/Scripts/python.exe scripts/update_keys.py --private-key "$env:USERPROFILE/.codex/excel-voucher-update/signing-key.pem" --manifest-url https://github.com/shelleyaeel-rgb/excel-voucher/releases/latest/download/latest.json --generate
```

每次发布先提高 `xiaoyu/__init__.py` 中的三段版本号，准备 UTF-8 更新说明文件，然后执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/publish.ps1 -NotesFile outputs/update-notes.txt
```

这条命令先测试并打包，生成固定的 `dist/❤/❤.exe` 和 `release/❤.zip`，再校验交付 ZIP、自检包内程序、创建 GitHub 发布草稿、上传完整程序和签名版本清单，复验远端附件后才公布为最新版。已经构建并验证过的同一包可加 `-SkipBuild`；上传前仍会重新校验和自检。发布优先读取 `GITHUB_TOKEN`，没有时使用本机 Git 为这个仓库保存的凭证，不把发布凭证写入文件或传给客户端。仓库必须允许公开下载，发布账号需要 Release 写权限。

本地 ZIP 固定名为 `❤.zip`，包内顶层目录与启动程序固定为 `❤/❤.exe`。GitHub 可能规范化网页附件中的特殊字符，发布工具以它实际返回的、固定到版本标签的下载地址生成签名清单，客户端缓存仍使用 `❤.zip`。同版本号不能覆盖发布；失败草稿不会替换原最新版，先核对草稿后再决定重试方式。签名私钥要单独备份；丢失后已有客户端无法信任重新生成的钥匙，不能直接换钥匙继续发布。

如果上传程序包后发布中断，可在核对草稿编号后使用 `scripts/publish.ps1 -NotesFile outputs/update-notes.txt -SkipBuild -ResumeDraft <草稿编号>` 继续。它只接受同仓库、同版本、仍为草稿、且只含一份大小与 SHA-256 均匹配的程序包的草稿，不重新上传或覆盖附件；存在版本清单或其他附件时需要人工核对。签名清单使用发布后的固定版本地址，不使用 GitHub 草稿的临时下载地址。

此前没有更新功能的版本需要手动换成一次 0.4.0 或更高版本，之后才会自动接收更新。这里的客户端更新与下面构建脚本替换发布者本机产物是两个步骤。

## 开发与构建

仓库内置模板为脱敏示例：已清除填写的凭证，单位、人员和银行账户名称已替换为示例名称。代码中的平台名称及测试数据名称也已同步替换。实际记账前请使用自己的账套模板，并核对科目和户名对应关系。

`data/`、业务导出目录 `outputs/`、构建与发行产物、虚拟环境和本机密钥文件不纳入 Git 提交。

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe main.py
```

运行测试：`.venv/Scripts/python.exe -m pytest -q`。

关闭正在运行的便携程序后打包：`powershell -ExecutionPolicy Bypass -File scripts/build.ps1`。
打包脚本先在 `outputs/build-staging/<唯一编号>/❤` 构建，不覆盖现有程序。新包通过校验后，自动更新正式程序目录和 ZIP；原程序目录与原 ZIP 完整备份至 `outputs/release-backups/<唯一编号>/`。
如果 Windows 仅阻止移动整个正式目录，发布工具会先完整复制并核对旧程序及全部用户文件，再按旧／新交付包清单逐个替换程序文件，用户文件留在原位。全部程序文件核对成功后才切换交付 ZIP；失败时还原旧程序。中断记录位于 `outputs/pending-publication.json`，再次发布时先恢复；若中断后发现用户新写入的同名文件，会保留该文件并停止自动覆盖。此方式只用于发布者本机正式目录，客户端仍由独立更新器在退出后更新。
脚本根据旧交付 ZIP 的程序文件清单，迁移原程序目录中的 `data`、用户源表、导出结果及其他额外文件。缺少可靠旧清单、用户文件与新程序重名或正式程序被占用时停止；切换失败时恢复原正式目录。旧程序暂时无法关闭时，可先在项目内暂存目录完成构建，关闭旧程序后再执行 `scripts/package_release.py --app-dir <暂存目录/❤>`，完成校验与自动更新。
生成 `dist/❤/❤.exe` 和 `release/❤.zip`。免安装程序名固定为 `❤.exe`、目录名固定为 `❤`，不附带版本号或日期；软件界面仍显示“给小雨的软件”。压缩包内的启动路径同样是 `❤/❤.exe`。
每次发布先在暂存位置生成新程序和压缩包，通过 ZIP 完整性检查与新包程序的可运行自检后，才替换正式产物并清理本项目生成的旧版免安装目录和压缩包；成功发布后仅保留当前 `dist/❤/` 目录和一份 `release/❤.zip`。
构建或校验失败时保留原有可用包。清理不涉及用户源表、`data` 配置、导出结果或其他文件，也不会无差别删除其他 ZIP 文件。命令行发布只接受干净的构建暂存目录，不会直接重建已使用的正式目录的程序清单，以免把其中的用户额外文件误打进公开更新包。
assets 中的图标、账套模板、公开更新配置以及独立更新器随程序分发；outputs、data、签名私钥、发布凭证和业务源表不打包。构建脚本先生成 onefile 独立更新器，再构建主程序，最后生成程序文件清单；直接运行 `xiaoyu.spec` 需要先提供已构建的更新器路径。

## 模块

- `spreadsheet_io.py`：读取表格、金额标准化、按模板导出和核对清单。
- `engine.py`：科目匹配、手续费配对、工资/社保、平台结算与计提。
- `accounts.py`：统一解析科目编码、完整名称和下拉显示文本，歧义或矛盾输入保留待核对。
- `service.py`：输入汇总、重复文件检查和生成入口。
- `imports.py`：四类资料列名建议、确认后的解析与校验、银行／工资适配。
- `import_ui.py`：多工作表列对应确认、资料筛选预览与来源查看。
- `material_store.py`：公司隔离的 SQLite 资料库、读取格式、重复提示与清单导出。
- `models.py`：金额使用 Decimal，按分四舍五入。
- `ui.py` / `theme.py`：粉色桌面界面、异步任务、预览失效保护。
- `config.py`：便携模式本地设置。
- `ai_ui.py`：独立财务助手页面、附件、异步请求与手动下载。
- `ai_service.py`：固定 Luna 的官方 API 连接、云端文件处理、流式响应与下载。
- `ai_settings.py`：Windows 密钥加密保存与独立月度用量估算。
- `ai_rules.py`：独立保存、读取和校验财务助手的长期规则。
- `wps_service.py` / `assets/wps_airscript.js`：加密文档绑定、WPS HTTP 接口和通用云端脚本。
- `cloud_tools.py`：按列名读取、业务键匹配、修改预览、分批更新、独立回读及持久化任务记录。
- `wps_ui.py`：云文档连接配置、只读校验和历史修改明细。

引擎不修改输入。未知科目留空并记录来源；导出不因资料缺失阻断。每张凭证单独检查借贷平衡。
支持多个源文件，但只有完全相同文件按内容去重，不会仅凭同名同额删除可能真实重复的交易。
本地导入流程将源表中的文字仅作业务数据，不执行公式、宏、指令或网络请求。财务 AI 助手只上传用户在该页面明确选择并发送的文件，云端处理与本地导入流程独立。

平台默认往来结算，可选同一凭证内确认收入与结算。计提是显式选项，默认关闭；
金额所属月份取 `Options.period`，入账月份由 `Options.accrual_period` 控制。
详细使用步骤和限制见 `使用说明.txt`。

```powershell
$p = Start-Process -FilePath 'dist/❤/❤.exe' -ArgumentList '--self-test', 'outputs/qa/package-smoke.json' -PassThru -Wait -WindowStyle Hidden
$p.ExitCode
```

自检使用合成数据验证内置模板、科目名称解析、无效科目非阻断、两种 Excel 格式往返、四类资料列对应、重复导入、公司隔离、资料导出与 GUI 初始化；另以离线模拟服务验证财务助手的上传、回答、生成文件列表、源文件保护、密钥加密、用量记录和长期规则，以及 WPS 配套脚本打包、绑定加密、自动表头定位、按业务键更新、回读与任务记录。开发环境中的 WPS 跨层测试使用 Node.js 执行真实 AirScript 代码的合成工作簿；运行免安装程序不需要 Node.js。
自检不会连接 OpenAI、读取用户源表或修改用户配置，报告中的 `finance_ai.mode` 为 `offline_mock`。真实账号的 Luna、云端文件处理权限、余额和生成质量须在填写密钥后另外验证。
